# 会社で使う前の点検表

会社のリポジトリで agent-crew を動かす前に、上から順に確かめる。チェックの記録は手元に残し、**会社の情報(社名、プロジェクト名、チケットの内容、認証情報)をこのリポジトリに入れない**。

## 1. ルールの確認(人が行う。設計メモ 7.4)

- [ ] 会社で AI コーディングツール(Claude Code)を使ってよいか。使ってよいリポジトリの範囲
- [ ] ソースコードを外部の API(Anthropic)に送ってよい範囲。顧客データや秘密情報の扱い
- [ ] 使うアカウント(会社契約のサブスクか、個人か)。`ANTHROPIC_API_KEY` を使わないこと(従量課金になる)
- [ ] 個人で作ったツールを会社で使うことについての就業規則(副業・知的財産)

## 2. このPCの準備

- [ ] [導入手順](setup.md)のとおり入れ、`npm test` と `npx agent-crew doctor` が通る
- [ ] `npx agent-crew doctor --probe-sandbox` がすべて ✓(push の拒否、worktree 外への書き込みの拒否、資格情報が見えない、読ませないパスが読めない)
- [ ] `sh scripts/verify-safety.sh` が通る
- [ ] 環境変数に GitHub などの認証情報があっても、エージェントには渡らないこと(`doctor` の github-credentials と、probe の env-credentials)

## 3. 対象のリポジトリの点検

- [ ] `.claude/settings.json` と `.mcp.json` の有無を確かめる(`doctor` が知らせる)。エージェントの実行では読み込まない(`--setting-sources ""`、`--strict-mcp-config`)が、人が Claude Code を使うときのために中身を見ておく
- [ ] 鍵、本番の設定、顧客データなど、エージェントに読ませないファイルを洗い出し、`agent-crew project protect <名前> --add <パス>` で足す(`.env` と `.env.*` は既定で読ませない)
- [ ] `project show` でプロファイルのコマンド(依存の準備・テスト・起動)を確かめ、必要なら `project set` で直す
- [ ] 依存の準備に、許可していないドメイン(社内のパッケージのレジストリなど)が要るか。要るなら `config.json` の `sandbox.allowedDomains` に足す(最小限に)
- [ ] push は人が手元で行う運用であることを、チームに伝える(エージェントは push も PR の作成もしない)

## 4. 試しの一周

- [ ] 小さなチケット(1ファイルで済む不具合の修正など)を1つ投入し、計画 → 実装 → レビュー → QA → 統合まで見届ける
- [ ] 計画とレビューの内容、差分、テストの結果を人が確かめる
- [ ] 所要時間と費用(GUI のタスク詳細)、利用枠の使用率(GUI のヘッダー)を記録する。消費が大きければ、役割ごとのモデル(`roles`)や同時実行数を見直す
- [ ] `task report <id>`(または GUI の報告の欄)で、チケットに貼る文面を確かめる
- [ ] ブランチを人が push し、PR をいつもどおり作る

## 5. 運用中に気をつけること

- 利用枠は対話の利用と共有される。上限に近づくと自動で一時停止し、リセットの後に再開する(`limits.pauseAtUtilization`)
- 人の対応待ち(承認・回答・失敗)は macOS の通知で知らせる。`config.json` の `notify` で止められる
- 完了・取り消しのタスクの worktree は自動で片付く(ブランチは残る)。未コミットの変更がある worktree は残して警告する
- Claude Code を更新したら `doctor --probe-sandbox` をやり直す
