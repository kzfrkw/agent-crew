# 戦略(GUI)

ツール全体の目的と方針は `docs/design-memo.md` が正本。このファイルは、フェーズ2以降のGUI(ローカルのWeb画面)の戦略だけを書く。

## プロダクトブリーフ

- **誰の**: このツールを自分のMacで動かす開発者本人(1人。複数ユーザーは非スコープ)
- **何の課題を**: エージェントが自律的に進める間、(1) 人の対応が必要なタスク(承認待ち・回答待ち・失敗)を見落とし、パイプラインが止まったまま放置される。(2) いま何が起きているか(どの役割が何をしているか、なぜその判定になったか)を、CLI の `task show` やファイルを開いて追うのが手間
- **どう解くか**: ブラウザを開けば、「人の対応待ち」と「エージェントの実況」が同じ重さで一目で分かり、そこから判断材料(計画・レビュー・QAの結果、実行ログ)へ1〜2クリックで辿れる画面を用意する。更新はSSEで即時に反映する
- **フェーズ2の制約**: 読み取り専用。操作(承認、回答、引き継ぎ)はCLIのまま。画面には、必要な操作の CLI コマンドをコピーできる形で示す。操作できるGUIはフェーズ3

## ペルソナ

**開発者本人(個人PC / 会社PC)**
- ふだんはエディタとターミナルで作業し、エージェントには別タスクを並行で任せている
- ブラウザのタブに agent-crew を開きっぱなしにして、ときどき目をやる。通知が来たら開く
- 知りたいのは「自分の番が来ているか」「エージェントは順調か、詰まっていないか」「なぜこの判定になったか」
- 費用(利用枠)の消費を気にしている

## 成功の基準

- 開いて3秒で「自分の対応が必要なタスクがあるか」が分かる
- 対応待ちのタスクから、判断に必要な成果物(plan.md など)を1クリックで読める
- 実行中の役割の最新の動き(発言・ツール実行)が、再読み込みなしで流れてくる
- 1タスクの費用と所要時間が分かる
