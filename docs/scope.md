# 要件(GUI・フェーズ2)

戦略は `docs/strategy.md`。フェーズ2は読み取り専用GUIの本格化(設計メモ13章)。

## 機能一覧

| # | 機能 | 内容 |
|---|------|------|
| F1 | 対応待ちの一覧 | `needs_input` / 承認待ち / `failed` / `human_working` のタスクを最上部にまとめる。理由(回答待ちの質問、失敗の理由)と、次に打つ CLI コマンドを添える |
| F2 | 実況 | 実行中の役割(タスク、役割、モデル、経過時間)と、全タスクの最新イベント(発言、ツール実行、状態変化)が流れる |
| F3 | タスク一覧 | プロジェクトごとのタスクと状態、実行中の役割、差し戻し回数、更新日時。完了・取り消しは既定で畳む |
| F4 | タスク詳細 | 状態、パイプライン上の位置、チケット本文、worktree とブランチ、承認(有効/失効)、成果物、実行の履歴、費用と所要時間の合計 |
| F5 | 成果物ビューア | Markdown を整形して表示(先頭の判定 frontmatter はバッジで表示)。画像、テキスト、差分もそのまま表示 |
| F6 | 実行ログ | 1回の実行のイベント(発言、ツール実行と結果、警告)を時系列で表示。実行中は追記されていく。生ログ(`stream.jsonl`)へのリンク |
| F7 | プロジェクト | プロファイル(承認状態、テスト基盤)、リポジトリ、設計判断ログ(`decisions.md`)、プロジェクト把握担当の実行 |
| F8 | 即時反映 | SSE で変化を受け取り、開いている画面を更新する。接続状態を表示し、切れたら自動で再接続する |
| F9 | CLI コマンドのコピー | 承認・回答・引き継ぎなど、その状態で必要なコマンドをワンクリックでコピー |

## ユーザーストーリー

- 開発者として、ブラウザを開いたら、自分の対応が必要なタスクが最上部に見えてほしい。放置を防ぐため
- 開発者として、計画の承認待ちのタスクから plan.md をすぐ読みたい。承認の判断をするため
- 開発者として、回答待ちのタスクの質問と、回答するコマンドを見たい。すぐ答えるため
- 開発者として、実行中のエージェントの発言とツール実行を、再読み込みせずに眺めたい。詰まっていないか確かめるため
- 開発者として、レビューで差し戻された理由と、その後の修正を時系列で追いたい。判定の妥当性を確かめるため
- 開発者として、タスクごとの費用と時間を知りたい。利用枠の消費を把握するため
- 開発者として、プロジェクトのプロファイルと設計判断ログを読みたい。エージェントが前提にしている情報を確かめるため

## スコープ外(フェーズ2ではやらない)

- 操作(チケット投入、承認、回答、停止、再実行、引き継ぎ、エディタで開く)→ フェーズ3
- Notion 取り込み → フェーズ3
- 認証、複数ユーザー、他のPCからのアクセス(`127.0.0.1` のみ)
- デスクトップ通知(ブラウザ通知)→ フェーズ3で操作と合わせて検討
- 費用のグラフや期間集計(合計値の表示まで)
- 検索・全文検索
- モバイル表示の作り込み(崩れない程度に対応)
